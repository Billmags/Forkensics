# Development Rules

1. Plan before coding.
2. Claude is the only application-code author.
3. No build step begins until Bill, Claude, and Codex have reviewed the same written proposal.
4. Bill gives the final explicit approval.
5. Each proposal must define objective, included scope, excluded scope, user experience, data impact, privacy impact, acceptance criteria, tests, risks, and open questions.
6. Implementation must stay within the approved step. New ideas return to planning.
7. Claude supplies a change summary, changed-file list, tests run, results, and known limitations.
8. Codex reviews the implementation and evidence against the approved acceptance criteria.
9. A step is complete only after Bill accepts it.
10. Decisions and scope changes are recorded in `10_Decisions`.
11. No secret, credential, private photograph, or precise location is committed to source control or pasted into planning documents.
12. Executable database migrations and production code belong to Claude, not Codex.
